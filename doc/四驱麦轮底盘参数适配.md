# 四驱麦轮底盘参数适配与校准

本文记录把 `底层驱动/` 中 STM32H743 参考工程的电机/底盘参数迁移到当前
ESP32-S3（AT8236 + PCNT）工程的过程，以及首次上电必须做的方向与里程标定。

## 1. 目标硬件与参考工程

- 当前工程：ESP32-S3 四驱麦轮驱动板，AT8236 双路 PWM 驱动，PCNT 四倍频编码器。
- 目标底盘：原来由 `底层驱动/` 下的 STM32H743 工程控制的那套四驱麦轮底盘。
- 参考文件：
  - `底层驱动/Drivers/User/Inc/mecanum_kinematics.h`
  - `底层驱动/Drivers/User/Src/tb6612_motor.c`
  - `底层驱动/Drivers/User/Src/encoder.c`
  - `底层驱动/Drivers/User/Inc/wheel_output_control.h`
  - `底层驱动/Drivers/User/Src/navigation_controller.c`

## 2. 参考工程中的关键参数

| 参数 | STM32 参考值 | 说明 |
| --- | --- | --- |
| 轴距（前后） | `0.30 m` = 300 mm | `ROBOT_WHEEL_BASE` |
| 轮距（左右） | `0.35 m` = 350 mm | `ROBOT_TRACK_WIDTH` |
| 车轮半径 | `0.04 m` = 40 mm | 80 mm 麦轮 |
| 编码器每轮转脉冲 | `68000` | `ENCODER_PPR`，已含 4 倍频和减速比 |
| PWM 频率 | 20 kHz | TB6612 / AT8236 均适用 |
| PWM 量程 | `0..1000` | `MOTOR_PWM_MAX` |
| 电机安装方向 | A/B/C/D = `-1/+1/+1/-1` | A=左前, B=左后, C=右后, D=右前 |
| 编码器方向 | 1/2/3/4 = `-1/-1/+1/+1` | 1=左前, 2=左后, 3=右后, 4=右前 |
| 速度环 Kp | `7.5` | 单位：PWM / RPM（PWM 量程 0..1000） |
| 速度环 Ki / Kd | `0 / 0` | 参考工程为纯比例速度环 |
| 速度环输出限幅 | `±1000` | |
| 驱动死区 | `200` = 20% | `WHEEL_PWM_DEADZONE` |
| 目标转速斜率 | `500 RPM/s` | `WHEEL_TARGET_SLEW_RPM_S` |
| 手动速度限幅 | `0.3 m/s`, `1.0 rad/s` | `NavController_SetManualVelocity()` |
| 运动测试转速 | `200 RPM` ≈ `0.84 m/s` | `MOTION_TEST_SPEED_RPM` |

> `68000` 是“车轮转一圈”的计数，不是电机轴转一圈。STM32 的 TIM 编码器模式
> 和 ESP32 的 PCNT 都做了 4 倍频，因此这里直接使用 68000，不能再乘 4 或乘
> 减速比。

### 轮序映射

当前固件使用 `[FL, FR, BL, BR]`；本表按 `tb6612_motor.c` 的标注取
`A/B/C/D = [FL, BL, RR, FR]`。因此方向表重排为：

| 轮位 | 电机方向 `kMotorSigns` | 编码器方向 `kEncoderSigns` |
| --- | --- | --- |
| FL 左前（A） | `-1` | `-1` |
| FR 右前（D） | `-1` | `+1` |
| BL 左后（B） | `+1` | `-1` |
| BR 右后（C） | `+1` | `+1` |

```cpp
static constexpr int kMotorSigns[4]   = {-1, -1, 1, 1}; // FL, FR, BL, BR
static constexpr int kEncoderSigns[4] = {-1, 1, -1, 1}; // FL, FR, BL, BR
```

> 这里假设 ESP32 板的 FL/FR/BL/BR 电机与编码器接口，按丝印接到对应位置的
> 车轮；并且电机线序与原来 STM32 底盘一致。若接线不同，必须先按第 5 节
> 重新标定，不能直接跑闭环。

## 4. 首次上电前检查

1. **架空前轮和底盘**：让四个轮子全部离地，防止方向错误导致车辆冲撞。
2. **确认供电和急停**：手边保留断电开关；先不接 ROS 导航，只用低速手动指令。
   四驱同时启动电流较大，建议先用限流电源，并确认 AT8236 的供电电压与
   持续/峰值电流大于电机堵转电流。
3. **确认底盘类型**：Web 配置页选择 `Mecanum`。如果 NVS 里保存过
   `Differential`，刷新后仍然是差速模式，需要重新选择并重启。
4. **确认电机/编码器接线**：电机相线、编码器 A/B、编码器电源和地不要插错；
   编码器 A/B 接反只会导致方向相反，不会损坏，但电机相线短路会损坏驱动。
   同时确认编码器输出电平不超过 3.3V（ESP32-S3 GPIO 不耐 5V）；如果是 5V
   编码器，确认板上已有电平转换/分压，否则不要直接接。

启动日志会打印 `Chassis config: wheelbase=... track=... wheel=... counts/rev=...`
以及 `Motor signs:` / `Encoder signs:` 两行，可先用它确认新参数确实已经烧录。

## 5. 方向标定（必须做）

### 5.1 单轮/整车前进

在 PC 上发布低速前进指令：

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.05, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
```

观察四个轮子：从车后向前看，轮子应把车“向前”推（轮子顶部向车头方向转）。
若某个轮子反转，只翻转该轮在 `kMotorSigns` 中的符号。

若某个轮子越转越快、PID 明显饱和或来回猛冲，说明该轮编码器方向反了：
立即松开指令，翻转该轮在 `kEncoderSigns` 中的符号，再试。

### 5.2 横移

X 型麦轮在 `+y`（向左）时，正确的轮子转向是：

| 轮位 | `linear.y = +0.1` 时的转向 |
| --- | --- |
| FL | 反转 |
| FR | 正转 |
| BL | 正转 |
| BR | 反转 |

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.0, y: 0.1, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
```

如果横移时车走成斜线，通常不是符号问题，而是某个电机/编码器接在了错误的
轮位上。按“左前、右前、左后、右后”重新核对接线，再检查方向表。

### 5.3 自转

`angular.z = +0.5`（逆时针，从上往下看）时：

| 轮位 | 转向 |
| --- | --- |
| FL、BL | 反转 |
| FR、BR | 正转 |

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.5}}"
```

左右两侧转向相反、且与上表一致，说明方向表正确。

## 6. 编码器 68000 计数与里程标定

如果实际电机/编码器不是参考工程那套 68000 计数，`/odom` 的速度和距离会
整体偏大或偏小一个固定倍数。标定方法：

1. 在地面贴一条 1.0 m 的直线，车头对准起点。
2. 用低速直行指令走完 1.0 m，记录 `/odom` 的 `pose.pose.position.x`。
3. 计算修正：

   ```text
   新 kEncoderCountsPerWheelRev
     = 当前值 × (`/odom` 报告距离 / 实际行驶距离)
   ```

   例如实际走了 1.0 m，`/odom` 只报告 0.5 m，说明当前计数设得偏大，
   应把 68000 改为 `68000 × 0.5 = 34000`。反过来，`/odom` 报告 2.0 m
   而实际只走了 1.0 m，则应改为 `68000 × 2 = 136000`。
4. 也可以反过来先核对轮径：轮子直径不是 80 mm 时，先改
   `kMecanumWheelDiameterMm`，再按距离微调计数。

> 编码器计数和轮径都会影响线速度，但只有计数会影响“轮子转一圈对应多少
> 脉冲”。先确认轮径，再调计数，避免两个参数互相抵消。

## 7. 速度环整定

参考工程使用纯比例速度环 `Kp=7.5, Ki=0, Kd=0`（PWM 0..1000 / RPM）。
当前固件默认值与此一致。若实车表现不理想，用 ROS 服务在线调整并保存：

```bash
ros2 service call /set_speed_pid leap_interfaces/srv/SetSpeedPid \
  "{kp: 7.5, ki: 0.0, kd: 0.0}"
```

建议顺序：

1. **先只用 Kp**：从 5.0～7.5 开始，逐步增大到响应够快但不持续振荡。
2. **稳态速度偏低**：加入较小的 Ki，例如 0.5 → 1.0 → 2.0；每次观察 10 s
   以上。Ki 过大会在 20% 死区附近产生低速爬行/振荡。
3. **有高频抖动**：减小 Kp；一般不需要 Kd，编码器 68000 计数时微分噪声
   会被放大。
4. **低速不动或抖动**：说明死区 `kMotorPwmDeadband=200` 对这套电机偏大或
   偏小。实测“刚好能连续转动”的最小 PWM 后，把死区设为该值的 80%～100%。

> 旧固件曾在 NVS 的 `pid_cfg/speed` 保存过 PID。新固件改用
> `pid_cfg/speed_v2`，所以首次启动会使用上面的新默认值；之后通过
> `/set_speed_pid` 保存的参数会写入新键。

## 8. 常见现象与处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 四个轮子都反 | 电机方向表整体反了，或 `cmd_vel` 约定相反 | 四个 `kMotorSigns` 同时取反 |
| 四个轮子速度符号都反 | PCNT 原始计数方向与 STM32 TIM 整体相反 | 四个 `kEncoderSigns` 同时取反 |
| 单个轮子反 | 该电机线序/安装方向不同 | 只翻转该轮 `kMotorSigns` |
| 只有右侧两个轮子反 | 参考工程 C/D（右后/右前）标注可能互换 | 同时翻转 FR、BR 的 `kMotorSigns` |
| 轮子越转越快、停不下来 | 该轮编码器方向反了（正反馈） | 立即停机，翻转该轮 `kEncoderSigns` |
| 前进正常，横移走斜线 | 电机/编码器接到了错误轮位 | 按 FL/FR/BL/BR 重新核对接线 |
| 自转时整车平移 | 左右轮位接反或方向表错误 | 核对 5.3 的转向表 |
| `/odom` 距离是实际的 2 倍/一半 | 编码器计数或轮径设置不对 | 按第 6 节标定 |
| 静止时缓慢爬行 | 死区偏大、编码器噪声、PID 积分饱和 | 降低死区、检查编码器、重置 PID |
| 起步/换向冲击大 | 加速度限制偏大或机械间隙 | 降低 `kMaxAccelRpmPerS`，检查联轴器 |
| 电机发热/电流大 | 死区或 Kp 过大、轮子卡滞 | 降低死区/Kp，架空检查机械 |

## 10. 已知假设与未验证项

- 电机/编码器方向表来自 STM32 工程的安装标定，但 ESP32 板的接口丝印与
  实际车轮的对应关系需要在实车上按第 5 节确认。
- 参考工程的速度环是纯比例环，稳态可能存在速度误差；是否需要加 Ki 取决
  于实车电机和负载特性。
- 电机最高转速、真实死区、轮径和编码器计数都没有在本文中实测，建议首次
  调试时记录一组“PWM—转速”数据，再回到本文微调。
- 参考工程的逆运动学轮序注释存在不一致；当前固件使用标准 X 型麦轮公式
  （FL/FR/BL/BR），并以第 5 节的实车转向表为准。
- 参考工程 `encoder.h` 把编码器 3/4 标为右前/右后，而 `tb6612_motor.c`
  把电机 C/D 标为右后/右前，两者本身不一致。本表以 `tb6612_motor.c` 的
  电机编号为准；实车必须按第 5 节验证，不能只信注释。
